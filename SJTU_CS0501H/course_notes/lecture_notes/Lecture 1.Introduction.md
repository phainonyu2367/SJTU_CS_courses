## 算法
- 解决具体问题的具体方法和步骤
	- 确定性：条件和步骤有明确的含义，没有二义性
	- 有穷性：每一步在有限的时间内完成，整个算法的步骤为有限步
	- 可行性： 每一步都是可以经过有限次基本操作完成，没有复杂的算法
	- 有输入
	- 有输出（严格的来说，有操作）

#### 算法基本要求
- 正确性： 准确反映并能满足具体问题的要求
- 可读性：可供人们阅读的容易程度
- 健壮性（robustness）：对各种不同的输入有对应的反应（边界条件）
- 时间效率
	- 数据规模（数据量大小）
	- 程序算法优劣
	- 编译器生成的机器码优劣
	- 计算机性能优劣
- 空间效率

## 时间复杂度
通常来说，我们测算一个算法的时间效率，直接的想法是运行程序并直接测量这个程序运行的时间， 但是考虑到上面提到的编译器与硬件的影响，同时为了开发和设计的便捷，估算是一个更好的方式

我们考虑算法中基本语句执行的次数来估计算法的时间复杂度。

通常来说，我们会取程序的最差可能性来估计算程序的时间复杂度
case：
```
x = int(input())
for _ in range(1, x):
	print('executed')
```
时间复杂度为O(n)

这里的O(n)是由big-O notation表示的时间复杂度。通过计算运行时间的增长趋势的渐进上界函数T(n)来确定增长趋势的量级。


### 时间复杂度的运算定理
#### 求和定理
假设T1(n)、T2(n)分别是O(f(n)), O(g(n))的，那么T1(n) + T2(n)的时间复杂度是O(MAX(f(n), g(n)))

#### 求积定理
假设T1(n)、T2(n)分别是O(f(n)), O(g(n))的，那么T1(n) x T2(n)的时间复杂度是O(f(n)xg(n))

## 空间复杂度
程序本身由自己固定的内存占用（源代码的内存占用和输入数据的内存占用）。我们不考虑这些数据的内存空间占用，我们考虑在程序运行过程中辅助程序运行所产生的额外内存占用（如变量创建，函数创建等的开销）

空间复杂度的计量方法同时间复杂度，我们用big-O notation来估计额外空间利用的量级
